## 3. 评价标准

本次不直接判断“原神哪些东西好”，先建立评价标准。

| 标准 | 对《小小文明岛》的要求 |
|---|---|
| 文明一致性 | 交互必须服务“文明问题生成数学”，不能变成原神皮肤化 |
| 儿童可理解性 | 6-9 岁儿童不看说明也能理解目标和下一步 |
| 规则可见性 | 数学规则必须通过世界反馈被看见，不靠文字说明 |
| 短循环强度 | 30 秒内有目标，1-3 分钟内有反馈，10-15 分钟内有成长结果 |
| 核心设施心智 | 要有一个长期反复使用的世界设施，承载数学规则解锁 |
| 跨场景复用 | 一个数学规则必须在至少两个文明问题中复用 |
| 不增加无效复杂度 | 不引入战斗、队伍、抽卡、体力、复杂地图，避免压垮 MVP |
| 可验证 | 每条建议必须能转成儿童测试动作和成功/失败标准 |

## 4. 原神可吸收的 8 个交互理念

### 4.1 世界先吸引行动，再让规则解释反馈

原神结构：

```text
看见目标
-> 走过去
-> 遇到机关/怪物/资源
-> 用元素/角色解决
-> 得到反馈和奖励
-> 看见下一个目标
```

迁移到《小小文明岛》：

```text
看见文明危机
-> 走近/触摸/拖动
-> 发现工具不够用或规则不成立
-> 使用数学工具解决
-> 世界状态改变
-> 下一个文明问题自然显现
```

PRD 当前已有“远景目标牵引”，但还可以更具体：每一步都要有“远景、中景、近景”。

| 层级 | 原神启发 | 小小文明岛写法 |
|---|---|---|
| 远景 | 远处地标/神像/光柱 | 倒塌粮仓、断裂田埂、远处市场轮廓 |
| 中景 | 路上宝箱/采集/怪物 | 散落粮食、混杂材料、饿居民 |
| 近景 | 可交互机关/元素目标 | 石子、绳尺、分类槽、泥板、碗 |

建议进入 PRD：

> 每个文明瓶颈必须同时设计远景目标、中景干扰和近景工具，保证孩子不是读任务，而是被场景吸引行动。

### 4.2 数学规则要像元素反应

原神元素反应的交互价值：

- 单元素易懂。
- 两个元素组合产生新反馈。
- 同一规则可跨战斗、探索、解谜复用。
- 反馈立刻可见。

小小文明岛应建立“数学反应系统”：

| 数学工具/对象 | 世界状态 | 反应结果 | 数学含义 |
|---|---|---|---|
| 同类物资 | 放入同一槽 | 合并、槽亮起 | 同类才能相加 |
| 异类物资 | 放入同一槽 | 弹回、腐坏、无效 | 单位/类别不一致不能直接运算 |
| 人数 + 粮食 | 一一对应 | 有人吃饱/有人饿 | 数量比较 |
| 6 个种子 + 2x3 格田 | 播种成功 | 发芽稳定 | 阵列、面积密铺 |
| 6 个种子 + 1x6 格田 | 可播但低效 | 照料距离长，产量下降 | 同面积不同形状 |
| 粮食 + 泥板记录 | 第二天恢复 | 自动记住状态 | 符号记录和文明传承 |
| 木头 + 地基边界 | 建仓 | 容量/结构反馈 | 面积、容量、稳定性 |

建议进入 PRD：

> 把“数学知识点”统一改写成“数学反应”：对象 A + 对象 B + 世界状态 -> 可见结果。孩子先观察结果，再说出规则。

### 4.3 核心设施要长期存在

原神合成台启发：

- 它在世界内可见。
- 多地点重复出现。
- 承载材料升级、转换、药剂等多类转化。
- 与养成长期绑定。

小小文明岛当前有石子、分类槽、绳尺、单位格、泥板，但缺少一个长期中心设施。建议把 MVP 的长期设施定义为：

> **文明火堆 / 营地工坊**

它不是教学菜单，而是文明中心：

| 阶段 | 火堆/工坊能力 | 数学规则 |
|---|---|---|
| 第一天 | 清点人口与粮食 | 一一对应、数量比较 |
| 分类后 | 识别食物、种子、建材 | 分类、单位 |
| 分饭后 | 生成饭碗分配位 | 平均分、余数 |
| 量田后 | 生成田地图案 | 单位格、面积 |
| 建仓后 | 保存粮食容量 | 容量、空间组织 |
| 泥板后 | 保留第二天状态 | 符号、记录、传承 |

建议进入 PRD：

> 首版不要把工具散成一堆按钮。火堆/工坊是玩家回来的地方，也是规则沉淀的地方；每学会一种数学工具，火堆/工坊多一个可见功能。

### 4.4 角色不是抽卡单位，而是需求与反馈载体

原神角色的强点不是抽卡，而是角色同时承担玩法、情感、故事和世界入口。

《小小文明岛》不能抽卡，但可以让居民成为“文明需求角色”：

| 居民类型 | 世界需求 | 数学功能 | 反馈方式 |
|---|---|---|---|
| 饥饿居民 | 要吃饭 | 一一对应、分配 | 吃饱/虚弱/恢复行动 |
| 建造居民 | 要修仓 | 分类、面积、结构 | 搬得动/卡住/仓倒 |
| 记录居民 | 怕明天忘记 | 符号、记录 | 泥板完整/缺失 |
| 农作居民 | 要种田 | 测量、单位格 | 发芽/漏水/产量打折 |

建议：

> 不做“数学老师 NPC”，做“有真实需求的居民”。他们不用讲知识点，而是通过状态变化让孩子看见规则。

### 4.5 地图不是大，而是密度和目标管理

原神开放世界不是空旷自由，而是远景目标、中途诱因和到达反馈组成的密度场。

《小小文明岛》MVP 不该做大地图，但要做“小地图高密度”：

```text
营地中心：火堆/居民/工具
左侧：散落物资
右侧：冲坏田地
上方：倒塌粮仓
远处：市场/水渠剪影
```

每个点都对应一个文明问题。

建议进入 PRD：

> MVP 地图不追求面积，追求每个屏幕区域都有“世界问题 + 可触摸工具 + 规则反馈”。

### 4.6 成长不是经验条，而是文明能力解锁

原神用 Adventure Rank 和 World Level 逐步解锁系统和提高世界挑战。

《小小文明岛》可以借鉴“系统解锁”，但不要做经验条刷数值。建议改成“文明能力图谱”：

```text
数清楚
-> 分清楚
-> 分公平
-> 量准确
-> 建稳定
-> 记得住
-> 换得公
```

每个能力必须由世界状态证明：

| 能力 | 解锁条件 | 世界证明 |
|---|---|---|
| 数清楚 | 清点居民和粮食 | 所有人有饭 |
| 分清楚 | 分类物资 | 食物/种子/建材不再混放 |
| 分公平 | 平均分饭 | 三个居民都恢复行动 |
| 量准确 | 围出有效田地 | 种子发芽 |
| 建稳定 | 修成粮仓 | 第二天粮食没坏 |
| 记得住 | 泥板记录完整 | 第二天自动恢复状态 |

### 4.7 任务类型可以分层，但不能列表化

原神有主线、世界任务、每日委托、活动任务等层级。

《小小文明岛》可借鉴任务分层，但不能做成 UI 任务列表。

| 原神任务类型 | 小小文明岛对应 | 表达方式 |
|---|---|---|
| 主线任务 | 文明主瓶颈 | 洪水后生存、市场公平、水渠修复 |
| 世界任务 | 局部文明问题 | 某居民饿、某块田漏水、某仓容量不足 |
| 每日委托 | 自然日变化 | 第二天粮食、作物、居民需求变化 |
| 活动任务 | 创造挑战 | 用 6 格田做不同布局、设计最省材料粮仓 |

建议：

> PRD 中不要出现“任务列表驱动”，但可以有“问题层级系统”：主瓶颈、局部问题、自然变化、创造挑战。

### 4.8 版本运营要服务学习迁移

原神的版本更新用新区域、新角色、新机制维持长期生命。

《小小文明岛》可以把 Roadmap 改成“文明章节”：

| 版本 | 原 PRD 文明瓶颈 | 原神式产品包补强 |
|---|---|---|
| v0.1 洪水第一天 | 生存混乱 | 营地中心、基础工具、第一批居民 |
| v0.2 市场开张 | 交换不公平 | 市场区、秤、砝码、价格牌、商人居民 |
| v0.3 水渠与桥 | 水到不了田 | 水渠谷、绳尺、路径、桥梁材料 |
| v0.4 星星和农时 | 不知道何时播种 | 观星台、日历、周期记录 |
| v0.5 图案工坊 | 建筑不好看也不稳定 | 纹样区、对称、平移、旋转 |
| v0.6 岛外贸易 | 记数方式不同 | 港口、异族数字、算盘、账本 |
| v0.7 自动营地 | 重复工作太多 | 机关区、流程、条件、自动化 |

建议：

> 每个版本不是一个知识点，而是一个完整区域产品包：文明问题 + 数学规则 + 工具 + 居民 + 建筑 + 新反馈。

## 5. 不应照搬原神的内容

| 原神机制 | 为什么不能照搬 | 小小文明岛替代方案 |
|---|---|---|
| 抽卡 | 儿童产品不应把学习能力随机化和付费化 | 居民通过文明问题自然加入 |
| 树脂体力 | 会把学习动机变成等待/付费 | 用自然日变化控制节奏，不限制学习 |
| 战斗数值 | 会抢走数学规则注意力 | 用世界后果、资源损失和效率差异反馈 |
| 四人队伍切换 | 6-9 岁首版认知负担高 | 只保留 2-3 个居民角色状态 |
| 大开放世界 | 成本高，目标不清 | 小地图高密度文明问题 |
| 大量剧情文本 | 低年级阅读负担重 | 场景状态、短句、动作反馈 |
| 高频日常任务 | 会把学习变成负担 | 每日自然变化，不做打卡压力 |

## 6. 对《小小文明岛 PRD》的具体补强建议

### 6.1 增加“数学反应系统”章节

建议插入到当前 PRD 第 9 章系统架构后。

```text
数学对象
-> 世界状态
-> 玩家操作
-> 数学反应
-> 世界反馈
-> 儿童解释
```

示例表：

| 反应名 | 输入 | 条件 | 结果 | 儿童解释目标 |
|---|---|---|---|---|
| 同类合并 | 木头 + 木头 | 同用途 | 建材数量增加 | “一样的东西才能一起数” |
| 异类弹回 | 木头 + 谷物 | 不同用途 | 不能合成，谷物腐坏 | “它们不是同一种东西” |
| 公平饭桌 | 3 份饭 + 3 人 | 每人 1 份 | 全员恢复 | “每个人都有一份才公平” |
| 阵列发芽 | 6 种子 + 2x3 田 | 单位格闭合 | 发芽稳定 | “2 排，每排 3 个，一共 6 个” |
| 长形低效 | 6 种子 + 1x6 田 | 面积够但太长 | 产量打折 | “一样多，但照顾起来更远” |

### 6.2 增加“文明火堆/营地工坊”作为长期设施

当前 PRD 工具很清楚，但缺少像原神合成台一样的长期心智锚点。

建议：

- 火堆是居民聚集点。
- 分类槽、碗、泥板、绳尺围绕火堆逐步出现。
- 每解决一个文明问题，火堆周围多一个永久设施。
- 第二天从火堆开始，孩子能看到昨日成果。

验收：

> 4/6 儿童完成试玩后能指出“以后要回到哪里继续帮小岛”。

### 6.3 将“远景目标牵引”细化为三层目标

建议把当前“远景目标牵引”细化：

| 层 | 设计对象 | MVP 例子 | 成功标准 |
|---|---|---|---|
| 远景目标 | 让孩子想去 | 倒仓、断田、市场剪影 | 4/6 儿童能指出“那里也出问题了” |
| 中景目标 | 让孩子路上有事 | 散粮、混杂材料、居民动作 | 4/6 儿童主动触摸其中一个 |
| 近景工具 | 让孩子能行动 | 石子、绳尺、泥板、碗 | 4/6 儿童使用一个工具 |

### 6.4 把居民改成“规则反馈角色”

当前居民主要表达饥饿、恢复行动。建议增加差异化角色状态：

| 居民 | 初始状态 | 数学规则触发 | 反馈 |
|---|---|---|---|
| 小禾 | 饿，盯着粮食 | 一一对应/分饭 | 吃饱后去田边 |
| 石叔 | 想修仓但材料混乱 | 分类/建材数量 | 材料正确后开始搬木头 |
| 泥婆 | 担心明天忘记 | 记录/符号 | 泥板完整后点亮 |

注意：不要让他们讲课，只让他们“需要”和“反应”。

### 6.5 重写第一分钟体验

建议第一分钟按原神“看见目标 -> 走近 -> 反馈”来设计：

```text
0-5 秒：镜头扫过水痕、饿居民、散粮、倒仓
5-10 秒：一个居民短句：“今晚够吃吗？”
10-20 秒：石子轻微发光，粮食和居民形成视觉对应
20-40 秒：孩子拖动石子/粮食，居民即时反应
40-60 秒：分配结果改变居民状态，一个居民走向散乱物资
```

这比直接给工具说明更符合“环境即教程”。

## 7. 反方观点

### 7.1 最强反方

> 原神的交互成立，依赖高品质 3D 世界、美术、音乐、角色、战斗和长期内容产能。《小小文明岛》是低成本 2D 教育原型，过度参考原神可能导致范围膨胀、成本失控和目标偏移。

这个反方成立。对策不是“更像原神”，而是只抽取 4 个结构：

1. 世界目标牵引。
2. 规则反应系统。
3. 长期核心设施。
4. 区域产品包。

### 7.2 具体反方风险

| 风险 | 为什么严重 | 应对 |
|---|---|---|
| 变成原神低配模仿 | 小学生和家长都会觉得粗糙 | 不学画风、战斗和抽卡，只学交互结构 |
| 加太多系统 | MVP 失焦 | 首版只保留火堆、石子、分类、分饭、量田、建仓、泥板 |
| 数学被玩法掩盖 | 孩子会玩但不会解释 | 每个反应都绑定儿童解释问题 |
| 文明史被幻想化 | 失去 civilization-history 方法论 | 每个机制必须回答“哪个文明需求产生这个数学工具” |
| 角色变讲师 | 回到教学卡 | 居民只表达需求和后果，不讲概念 |
| 任务列表回潮 | 破坏环境即教程 | 所有任务改成场景状态和角色动作 |

## 8. 下一步验证动作

| 动作 | 具体做法 | 成功标准 | 失败含义 |
|---|---|---|---|
| V1 首分钟重做 | 按“镜头扫场 -> 居民短句 -> 工具微光 -> 操作反馈 -> 下个目标显现”做纸面/低保真原型 | 4/6 儿童 30 秒内说出小岛出了什么问题 | 原神式目标牵引不成立 |
| V2 数学反应测试 | 做 5 个反应：同类合并、异类弹回、公平饭桌、阵列发芽、长形低效 | 3/6 儿童能解释至少 2 个反应 | 反应只变成试错，不形成理解 |
| V3 火堆设施心智测试 | 把工具围绕文明火堆逐步解锁 | 4/6 儿童能说出“回火堆继续做/看记录/修营地” | 核心设施心智没形成 |
| V4 远中近目标测试 | 同屏放倒仓、散粮、石子等三层目标 | 4/6 儿童不用任务列表也能连续完成两步 | 仍依赖 UI 任务 |
| V5 居民反馈测试 | 居民只通过状态变化反馈，不讲知识 | 3/6 儿童能根据居民变化修正分配/分类 | 反馈不可读 |
| V6 家长价值测试 | 给家长看“数学反应报告”：孩子触发了哪些反应、如何解释 | 4/6 家长能说出孩子学到的数学规则 | 家长仍觉得只是游戏 |

## 9. 推荐结论

《小小文明岛》最该吸收的原神交互，不是开放世界规模，也不是角色商业化，而是：

```text
世界目标牵引孩子行动
数学规则像元素反应一样产生可见结果
文明火堆/工坊像合成台一样成为长期核心设施
居民像角色一样承载需求和反馈
区域像国家一样成为“文明问题 + 数学工具 + 世界变化”的产品包
```

对 PRD 的直接建议：

1. 新增“数学反应系统”章节。
2. 新增“文明火堆/营地工坊”作为长期核心设施。
3. 把“远景目标牵引”细化为远景、中景、近景三层。
4. 把居民定义为“规则反馈角色”，不是讲课 NPC。
5. 重写第一分钟体验，减少文字，强化场景吸引和即时反馈。
6. 保留 PRD 的反照搬边界：不做抽卡、不做战斗、不做树脂、不做大开放世界、不做任务列表驱动。

最终判断：

> 原神可以帮助《小小文明岛》把“文明问题生成数学”从理念变成可玩的交互结构。关键不是像原神，而是让数学像原神的元素反应一样，成为世界里可观察、可组合、可复用、可解释的规则语言。
