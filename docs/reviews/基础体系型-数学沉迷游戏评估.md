## 2. 评价标准

以下标准由上面的事实推导，用于评估“让小学生沉迷学习数学”的游戏方案。

| 标准 | 评价问题 | 通过条件 | 失败信号 |
| --- | --- | --- | --- |
| S1 知识依赖清晰 | 游戏是否按基础数学依赖树推进？ | 先数与表示，再计算、比较、度量、比例、代数、数据、概率。 | 关卡散装，今天讲分数，明天讲概率，缺少依赖。 |
| S2 先分类再计算 | 孩子是否先知道对象属于哪类，才开始运算？ | 食物、木料、长度、面积、价格、概率事件等先被区分。 | 不同对象混加、混算，规则任意。 |
| S3 先表示再运算 | 游戏是否先让孩子建立表示方式？ | 数量、单位、格子、坐标、价格、比例尺先可见，再做运算。 | 直接给算式，孩子不知道数代表什么。 |
| S4 运算解释结构 | 加减乘除是否改变世界结构？ | 加法是合并材料，减法是消耗，乘法是重复阵列，除法是公平分配。 | 运算只是答题得分。 |
| S5 比较标准化 | 游戏是否让单位、比例、百分比、尺度成为公平比较工具？ | 交易、地图、建造、分配都需要统一单位。 | 只比较大小，没有标准和单位。 |
| S6 空间度量真实 | 长度、角度、面积、体积是否影响建筑和路径？ | 桥长、门宽、房间面积、塔高直接影响可用性。 | 几何只是图形识别。 |
| S7 一般化和算法 | 孩子能否把一次做法变成可复用规则？ | 配方、蓝图、自动机、路线图能复用。 | 每关都是一次性操作。 |
| S8 数据和概率不过早 | 统计和概率是否等前置能力成熟后再出现？ | 先计数、分类、记录，再做趋势和可能性。 | 早期就让低年级算概率或统计图。 |
| S9 沉迷来自能力成长 | 孩子是否因为“学会新能力”继续玩？ | 新规则解锁新建筑、工具、区域和自动化。 | 只靠金币、皮肤、积分驱动。 |
| S10 可验证学习 | 是否能通过行为和原话验证数学理解？ | 孩子能解释为什么这样合并、比较、测量、分配。 | 孩子能通关但说不出规则。 |

## 3. 方案评估

评估对象：用基础体系型方法设计一个让孩子沉迷学习数学的创造游戏。

| 标准 | 评分 | 评估 | 类型 | 置信度 |
| --- | --- | --- | --- | --- |
| S1 知识依赖清晰 | 高 | 基础体系型天然适合做长期成长树，可把数学能力设计成世界能力依赖。 | 推断 | 高 |
| S2 先分类再计算 | 高 | 分类能直接变成游戏底层规则，例如不同单位不能混算、不同材料不能混合。 | 推断 | 高 |
| S3 先表示再运算 | 高 | 数量、单位、格子、价格、坐标等都适合先可视化再计算。 | 推断 | 高 |
| S4 运算解释结构 | 中高 | 如果把加减乘除做成合并、消耗、复制和平均分，学习价值强；若做成题目则失败。 | 推断 | 中 |
| S5 比较标准化 | 中 | 交易、地图、建造都能承载单位和比例，但需要设计得非常具体，避免抽象化过早。 | 推断 | 中 |
| S6 空间度量真实 | 高 | 门、桥、房子、农田、仓库、地图都能承载长度、面积、比例和坐标。 | 推断 | 高 |
| S7 一般化和算法 | 中高 | 蓝图、配方、自动机很适合表达算法和公式；但要等孩子先经历具体操作。 | 推断 | 中 |
| S8 数据和概率不过早 | 中 | 该方向能做长线，但 MVP 必须切掉统计和概率，避免超出低龄认知。 | 推断 | 高 |
| S9 沉迷来自能力成长 | 中高 | 如果每个数学结构都解锁新世界能力，沉迷可能成立；但需要儿童测试证明。 | 假设 | 中 |
| S10 可验证学习 | 中 | 可以设计观察指标，但必须记录孩子原话和迁移行为，不能只看通关。 | 推断 | 中 |

## 4. 反方观点

| 反方观点 | 为什么严重 | 对应事实 |
| --- | --- | --- |
| 基础体系型容易变成“课程大纲游戏化”，不好玩。 | 如果按章节逐个做关卡，孩子会感到像学习软件。 | F1、F19 |
| 知识依赖树太长，MVP 容易变成什么都沾一点。 | 基础数学覆盖数、运算、比例、代数、几何、统计、概率，范围极大。 | F4-F10 |
| 低龄儿童无法感知“体系完整性”。 | 成人关心知识结构，孩子关心眼前能不能创造和变强。 | F2、S9 |
| 过早引入比例、代数、统计、概率会超龄。 | 材料中的递进路径说明这些能力依赖前置表示、计数、运算和比较。 | F4、F8-F10、F22 |
| 如果把数学能力都做成显性系统，会非常重。 | 单位、比例、坐标、数据、概率都做成玩法会带来高成本和高复杂度。 | F14-F18 |
| 学习验证难度高。 | 基础体系强调结构理解，孩子通关不代表理解分类、表示、运算和迁移。 | S10 |

## 5. 核心判断

| 结论 | 依据来源 | 原始证据 | 类型 | 置信度 |
| --- | --- | --- | --- | --- |
| 基础体系型最适合用来定义游戏的“能力依赖树”，而不是直接做章节关卡。 | `skills/basic-math-system-methodology/SKILL.md` | 基础数学不是零散知识点，而是从数是什么走向计算、比较、表达、度量、概括和判断的结构体系。 | 推断 | 高 |
| 第一版必须只验证“分类、表示、运算结构、空间度量”中的最前几层。 | 同上 | 核心递进路径从数的类型、数的表示、基本运算开始，再进入后续能力。 | 建议 | 高 |
| 游戏内数学应表现为世界能力：合并、消耗、复制、分配、测量、建造。 | 同上 | 运算要解释结构；几何负责空间度量。 | 推断 | 高 |

## 6. 可验证的下一步动作

| 动作 | 做法 | 成功标准 | 失败含义 | 对应标准 |
| --- | --- | --- | --- | --- |
| A1 分类理解测试 | 让孩子把材料放进食物、木料、石料等不同槽，并允许错误反馈。 | 4/6 能解释“这些能放一起，那些不能”。 | 分类规则不可理解，后续运算不稳定。 | S2 |
| A2 表示理解测试 | 在 HUD 和世界中显示数量、单位和格子，让孩子说出还差什么。 | 4/6 能说出“还差 1 个木头/还差 2 格”。 | 数字没有和物体建立映射。 | S3 |
| A3 加法结构测试 | 两份同类材料合并成一个包、梁或砖组。 | 4/6 能解释“两个合起来变多/变成一包”。 | 加法仍像题目，不是合并结构。 | S4 |
| A4 乘法阵列测试 | 用一排结构复制成多排，例如 3 格 x 2 排地板。 | 3/6 能说出“每排一样，有几排”。 | 乘法没有从重复结构中生长。 | S4、S6 |
| A5 除法分配测试 | 让孩子把食物平均分给 3 个村民。 | 3/6 能发现不平均会有人不满。 | 除法公平分配意义不成立。 | S4 |
| A6 单位比较测试 | 交易或建造时要求同单位比较，例如木头按根、食物按包。 | 3/6 能说出“这个不能和那个直接比”。 | 单位意识不足。 | S5 |
| A7 空间度量测试 | 让门宽、桥长、房间面积影响通行和居住。 | 4/6 能通过调整长度/面积解决问题。 | 几何没有成为空间度量。 | S6 |
| A8 规则复用测试 | 把同一个分类或测量规则用于两个系统。 | 3/6 能说“这里和刚才一样”。 | 没有形成一般化。 | S7 |
| A9 非超龄测试 | MVP 中不出现统计、概率、复杂代数术语。 | 不超过 1/6 孩子表示像上课或听不懂。 | 抽象层级过高。 | S8 |
| A10 原话验证 | 每名孩子结束后问“为什么这样能行，刚才为什么不行？” | 至少 3/6 能说出分类、数量、宽窄、平均等规则。 | 通关不等于学习。 | S10 |

## 7. 建议的最小原型

基础体系型下，第一版不要做全知识体系，只做前置能力闭环：

```text
第一座营地
-> 材料散乱
-> 孩子先分类：食物、木料
-> 再表示：数量、单位、格子
-> 再运算：合并食物包、消耗木料、摆 6 格地基
-> 再度量：门宽、房间面积、通行距离
-> 世界反馈：小屋能住，村民入住
```

该原型对应的基础体系路径是：

```text
分类
-> 表示
-> 基本运算
-> 单位比较
-> 空间度量
-> 可复用蓝图
```

## 8. 暂不建议做的内容

| 内容 | 暂缓原因 |
| --- | --- |
| 统计系统 | 数据概括位于后段，MVP 不应提前引入。 |
| 概率系统 | 概率前需要计数、事件和假设，不适合第一版。 |
| 复杂代数和方程 | 需要前置表示、运算和等量关系经验。 |
| 二进制和布尔逻辑 | 有体系价值，但不应干扰当前低龄数学主线。 |
| 完整课程地图 | 容易变成章节关卡，削弱游戏母体。 |

## 9. 当前决策

| 决策项 | 建议 |
| --- | --- |
| 是否继续该方向 | 继续。基础体系型适合作为产品能力树。 |
| 是否立即重构完整 PRD | 不建议。先把前五层能力做扎实。 |
| MVP 聚焦 | 分类、表示、合并/消耗、平均分、空间度量。 |
| 最关键指标 | 孩子能否说出“什么能放一起、还差多少、为什么这样住得下”。 |
| 最危险信号 | 孩子只是在跟任务走，不能解释分类、数量或空间规则。 |
