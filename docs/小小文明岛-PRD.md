# 小小文明岛 PRD

版本：v1.2  
日期：2026-06-24  
状态：原神交互启发融合版，在“文明问题生成数学”基础上加入数学反应系统、文明火堆/营地工坊、远中近目标牵引、规则反馈居民  

## 1. 背景

### 1.1 问题

当前要解决的不是“把小学数学知识点游戏化”，而是：

> 如何让小学生在玩一个真正有目标、有创造、有后果的游戏时，自然发现数学是让世界变有序、能协作、能建造、能交易、能传承的文明工具。

传统数学学习产品常见问题：

- 把数学做成题库、闯关、知识卡，孩子知道是在学习，游戏只是奖励包装。
- 把教材章节搬进游戏，形成“电子教材”，缺少真实动机。
- 把开放世界和建造玩法做出来，但数学只停留在背景皮肤，无法形成数学直觉。
- 孩子能通关，但说不清为什么这样做有效，无法迁移到新问题。

### 1.2 机会

`civilization-history-math-methodology` 的核心立场是：数学不是从教科书里突然出现的，而是从计数、度量、土地、贸易、天文、宗教、建筑、艺术、战争和科学需求中生长出来，再反过来改变文明。

这给本游戏一个更强的产品方向：

> 不做“数学题游戏”，而做“孩子亲手建立文明，数学是文明生存和扩张时被迫发明出来的工具”。

### 1.3 为什么现在

- 小学数学的早期核心本来就是从生活经验、实物操作、一一对应、分类、测量、合并、平均分、单位密铺进入抽象。
- 低成本 2D 原型足以验证核心假设，不需要先做完整开放世界或复杂 3D。
- 家长需要看到“孩子不是刷题，而是在形成数学直觉”的证据。

## 2. 产品概念

### 2.1 一句话定义

**《小小文明岛》是一款面向 6-9 岁小学生的 2D 文明建造数学游戏：孩子在洪水退去后的岛上清点粮食、分类物资、丈量田地、建造粮仓、制定分配规则，从文明问题中发明数学工具，并用这些工具让小岛持续成长。**

### 2.2 产品概念四格

| 项 | 定义 |
|---|---|
| 核心用户 | 6-9 岁小学低年级儿童，已接触数数、加减、分类、比较、长度测量或正在学习这些概念 |
| 典型场景 | 放学后、周末、亲子陪伴或独立玩 10-15 分钟 |
| 刚性问题 | 孩子觉得数学是题目和公式，缺少“为什么需要数学、数学怎样改变现实”的直觉 |
| 解决方案 | 用文明瓶颈驱动游戏目标，让孩子通过操作计数、分类、分配、测量、建造来解决世界问题 |

### 2.3 差异化

| 替代方案 | 问题 | 本产品差异 |
|---|---|---|
| 刷题 App | 数学是外部任务，游戏是奖励 | 数学是世界规则，不会数学则文明运转失败 |
| 教育动画 | 孩子被动观看 | 孩子亲手操作、试错、修正、建造 |
| 沙盒建造游戏 | 创造性强，但数学学习不可控 | 每个建造能力都来自明确数学工具 |
| 课程游戏化 | 容易变成章节闯关 | 从文明问题进入，再抽象出数学概念 |

## 3. 产品原则

### 3.1 总纲硬约束

1. **文明问题先于数学概念。** 不允许先弹出知识点、公式、方法卡。
2. **先操作，后命名。** 孩子先用石子、绳子、格子、仓板解决问题，再出现“计数、分类、测量”等名称。
3. **数学必须改变世界。** 学会一个数学工具后，岛上必须出现可见、持久的变化。
4. **错误必须有世界后果。** 分错粮、混放物资、量错田、建错仓，都要让孩子看到具体损失。
5. **同一规则必须跨场景复用。** 分类不能只用于仓库，也要用于合成、交易、建造；测量不能只用于田地，也要用于桥、路、房子。
6. **历史精神优先，历史包装克制。** 不做数学名人 NPC 讲课，不把历史变成卡片收集。
7. **每个功能都要能被儿童解释。** 孩子不能用自己的话解释“为什么这样能行”，功能就不算成功。
8. **环境即教程。** 首屏和每个新问题都优先用场景状态、角色状态、物品位置和可互动反馈引导，不用流程面板驱动。
9. **工具即能力。** 石子、分类槽、绳尺、单位格、泥板必须是世界里的实体工具，不是菜单按钮。
10. **错误即实验。** 错误不是失败结算，而是一次可观察、可修正的实验，让孩子从后果中反推规则。
11. **允许多解法，但必须可解释。** 只要数学关系成立，可以允许不同摆法、不同顺序、不同材料组合；但孩子必须能解释为什么成立。
12. **远景目标牵引。** 当前问题解决后，下一个世界问题必须自然显现或被角色行为指向，避免依赖任务列表。
13. **数学像反应，不像题目。** 每个知识点必须写成“对象 + 世界状态 + 玩家操作 -> 可见结果 -> 儿童解释”，不以算式题或知识卡开场。
14. **每屏必须有远中近目标。** 远处有想去的文明问题，中景有干扰和资源，近处有可操作工具，孩子靠场景读懂下一步。
15. **核心设施必须长期存在。** 文明火堆/营地工坊是玩家回流中心；每学会一种数学工具，火堆周围必须出现一个永久可见能力。
16. **居民是需求和反馈，不是老师。** 居民只表达饿、困、搬不动、记不住、修不好等世界状态，不讲公式、不讲概念。
17. **只吸收原神交互结构，不吸收原神外壳。** 不学抽卡、战斗、体力、四人队伍、长剧情和高成本开放世界，只学目标牵引、规则反馈、核心设施、区域产品包。

### 3.2 不做什么

| 不做 | 原因 |
|---|---|
| 不做独立答题关卡 | 会退化为题库游戏 |
| 不做知识卡片驱动 | 会把数学从世界规则变成说明书 |
| 不做完整开放世界首版 | 验证成本过高，容易失焦 |
| 不做全小学 1-6 年级内容首版 | 破坏教材依赖顺序 |
| 不做复杂战斗系统首版 | 会抢走数学生成机制的验证注意力 |
| 不做数学史名人导览首版 | 容易变成科普包装，而不是文明问题 |
| 不做自由物理沙盒首版 | 多解法只服务数学理解，不做主机级物理模拟 |
| 不做任务列表驱动首版 | 会削弱环境引导和主动探索 |
| 不做原神低配模仿 | 低成本 2D 原型照搬 3D 大世界会显得粗糙且失焦 |
| 不做抽卡、体力、四人队伍和高频日常 | 儿童数学游戏不应把学习动机绑定随机付费、等待压力或复杂养成 |

## 4. 用户与场景

### 4.1 目标用户

| 用户 | 需求 | 成功定义 |
|---|---|---|
| 小学低年级儿童 | 想玩、想建、想看到自己改变世界 | 愿意继续探索，并能解释一个数学规则 |
| 家长 | 想知道孩子不是只在娱乐，而是在形成数学理解 | 能从试玩录像看到孩子用数学解决问题 |
| 产品团队 | 想低成本验证方向是否成立 | 通过 6 名儿童测试判断 Go/No-Go |

### 4.2 核心用户任务

```text
当小岛遇到粮食、土地、居住和记录混乱时，
孩子想要让居民活下来并建起第一个营地，
以便看到自己用规则让世界变得有序、稳定、可继续发展。
```

### 4.3 核心痛点

| 痛点 | 产品回应 |
|---|---|
| 孩子不知道数学有什么用 | 所有数学都从生存、建造、分配、记录问题中出现 |
| 孩子只会答题，不会迁移 | 同一数学工具跨仓库、田地、建造复用 |
| 孩子觉得数学枯燥 | 数学带来可见世界变化和创造能力 |
| 家长担心只是玩游戏 | 提供可观察学习指标和儿童解释记录 |

## 5. Y 模型转化

| 表层请求 | 真实场景 | 底层需求 | 产品原则 | 选定方案 |
|---|---|---|---|---|
| 做一个让小学生沉迷学数学的游戏 | 孩子不愿刷题，家长期望理解数学 | 数学要从有意义的问题中被需要 | 文明问题先于知识点 | 洪水退去后建立第一个营地 |
| 像我的世界一样有创造性 | 孩子希望能建造自己的世界 | 学会规则后能创造更复杂结果 | 数学必须改变世界 | 用计数、分类、测量、分配建粮仓和田地 |
| 不要变成方法卡 | 旧方案容易教学化 | 数学要内嵌在行动和反馈里 | 先操作后命名 | 取消首版知识卡和公式面板 |
| 要体现数学史 | 泛故事无法体现文明史 | 数学从文明需求中生长 | 历史精神优先 | 用粮食、土地、记录、度量、历法等文明瓶颈组织玩法 |

## 6. MVP 范围

### 6.1 核心假设

> 如果孩子在一个文明危机中通过计数、分类、分配、测量、建造和记录解决问题，并看到世界状态因此改善，那么孩子会把数学理解为改变世界的工具，而不是题目。

### 6.2 MVP 名称

**洪水退去的第一天**

### 6.3 MVP 最小用户旅程

```text
进入小岛
-> 看到洪水退去后的混乱营地：文明火堆旁居民饿、粮食散、田地被水冲、旧仓倒塌
-> 孩子自由触摸和拖动物品，发现可用工具：石子、分类槽、绳尺、单位格、泥板
-> 围绕文明火堆触发第一个数学反应：人数 + 粮食 + 石子对应
-> 用石子清点幸存者和粮食
-> 用分类槽整理物资
-> 把饭分给居民，观察居民恢复行动
-> 用绳尺和单位格丈量第一块田，允许 2x3 或 3x2 等成立解法
-> 用单位格建第一座粮仓，观察容量和结构反馈
-> 在泥板上留下记录
-> 第二天小岛根据记录继续运转，并露出下一个世界问题
```

### 6.4 MVP 必须验证的问题

| 编号 | 验证问题 | 成功标准 |
|---|---|---|
| H1 | 孩子是否能在 30 秒内理解世界目标 | 4/6 儿童能说出“要帮他们活下来/建营地/整理东西” |
| H2 | 孩子是否理解数学动作来自世界需要 | 4/6 儿童能说出“要数清楚才知道够不够” |
| H3 | 孩子是否能独立完成核心操作 | 4/6 儿童能完成清点、分类、分配、丈量、建造中的至少 4 项 |
| H4 | 错误反馈是否有效 | 3/6 儿童能根据失败后果主动修正 |
| H5 | 是否形成继续探索欲 | 3/6 儿童完成后主动问还能建什么或下一天发生什么 |

### 6.5 MVP 范围表

| 范围 | 内容 |
|---|---|
| 必须做 | 2D 小岛场景、洪水后营地、文明火堆/营地工坊、居民、粮食、木头、石头、种子、石子计数、分类槽、绳尺、单位格、田地网格、粮仓建造、泥板记录、数学反应反馈、错误后果、居民状态、远中近目标牵引、多解法田地 |
| 明确不做 | 战斗、抽卡、装备、完整地图、多个文明时代、复杂经济系统、数学名人、知识卡片、公式讲解、多人联机 |
| 延后做 | 市场交易、历法、桥梁、航海、部落交流、位值制、算盘、对称建筑、图案工坊 |

| P0 | 规则反馈居民 | 居民通过状态变化表达数学规则后果 | 3/6 儿童能根据居民反馈修正一次操作 | 居民不讲课 |
| P0 | 实体数学工具 | 孩子把工具当成能力使用 | 4/6 儿童能主动拿石子、绳尺或泥板尝试 | 工具在世界中出现 |
| P0 | 清点幸存者和粮食 | 生成一一对应、计数、记录 | 孩子能把人数和粮食数量对应起来 | 石子/刻痕可视化 |
| P0 | 物资分类 | 生成分类标准、单位意识 | 孩子能按用途把物资放入不同区域 | 不用“分类”术语开场 |
| P0 | 第一顿饭分配 | 生成平均分、余数意识 | 分错有人饿，分对居民恢复行动 | 错误必须可见 |
| P0 | 多解法丈量第一块田 | 生成长度、面积、单位格、形状效率 | 孩子能用绳尺和格子围出 6 格可播种田，并理解 2x3/3x2 都成立 | 1x6 可作为低效但可讨论形状 |
| P0 | 建第一座粮仓 | 生成空间组织、容量、结构 | 粮仓容量够且能保存粮食到第二天 | 失败有漏粮/倒塌反馈 |
| P0 | 泥板记录 | 生成符号和可传承记录 | 第二天能按记录恢复粮食、人口、田地状态 | 体现文明记忆 |
| P0 | 远景目标牵引 | 当前问题完成后自然发现下一步 | 4/6 儿童不看任务列表也知道下一处问题 | 通过角色行动/场景变化引导 |
| P1 | 学习解释回看 | 帮家长看到学习价值 | 结束后展示孩子完成的工具链，不展示分数 | 用世界语言，不用课堂报告 |
| P1 | 规则迁移提示 | 防止一次性关卡 | 分类和测量在两个任务中复用 | 只在卡住时轻提示 |
| P2 | 多日循环 | 提供长期目标 | 第二天出现新问题 | MVP 后再做 |

### 7.2 KANO 分类

| 类型 | 功能 | 判断 |
|---|---|---|
| 基础型 | 世界目标清晰、可操作、错误反馈、保存进度 | 没有这些就不是可玩的游戏 |
| 期望型 | 建造反馈、居民反应、可见成长、复用规则 | 做得越好越能形成投入感 |
| 兴奋型 | 多文明工具、特殊建筑、跨岛贸易、历法奇观 | 后续版本增加惊喜 |
| 反向需求 | 大量题目、知识卡、讲解弹窗、名人说教 | 会破坏沉浸和文明生成逻辑 |

### 7.3 交互体验补充需求

| 交互原则 | 产品要求 | 验收方式 |
|---|---|---|
| 环境即教程 | 首屏问题必须由画面表达：饿居民、散粮、倒仓、水痕、乱物资 | 不解释试玩 30 秒，观察孩子第一句话 |
| 工具即能力 | 石子、绳尺、单位格、泥板必须能被拖动或点击使用 | 孩子能说“我用这个来数/量/记” |

## 8. 核心玩法细节

### 8.0 交互总原则：营地是可实验空间

MVP 的第一场景不是流程面板，而是一个可触摸、可试错的小营地。文明火堆/营地工坊位于营地中心，承担“回流中心 + 能力沉淀 + 第二天记忆”的作用。

```text
世界问题可见
-> 工具可触摸
-> 操作产生反馈
-> 错误产生后果
-> 孩子修正做法
-> 世界永久变好
```

首版不追求大地图自由，而追求一个小空间内的高密度规则实验。孩子可以按不同顺序触摸居民、粮食、物资、绳尺、田地、旧仓和泥板，但核心世界问题会通过角色状态、火堆变化和场景反馈把孩子拉回主线。

### 8.0.1 第一分钟体验脚本

第一分钟借鉴“看见目标 -> 走近目标 -> 触发反馈 -> 露出下一个目标”的交互节奏，但不照搬原神 UI 或战斗。

| 时间 | 画面/交互 | 目的 |
|---|---|---|
| 0-5 秒 | 镜头扫过水痕、饿居民、散粮、倒仓、断田，最后停在文明火堆 | 让孩子看见小岛出了问题 |
| 5-10 秒 | 一个居民短句：“今晚够吃吗？” | 用世界需求代替任务说明 |
| 10-20 秒 | 石子轻微发光，居民和粮食形成视觉对应 | 引导一一对应 |
| 20-40 秒 | 孩子拖动石子或粮食，居民即时有表情和动作反馈 | 让规则反馈立刻可见 |
| 40-60 秒 | 分配结果改变居民状态，一个居民走向混乱物资区 | 让下一个目标自然显现 |

验收：

- 4/6 儿童在 30 秒内能说出“小岛出了什么问题”。
- 4/6 儿童不用任务列表也能完成第一次触摸或拖动。
- 若儿童第一句话是“我要点哪个按钮/题在哪里”，说明首分钟失败。

### 8.1 首屏：洪水退去

场景：

- 小岛低洼处有水痕。
- 3 个居民站在文明火堆/营地工坊旁。
- 粮食、木头、石头、种子散落。
- 远处有被冲坏的田埂和倒塌的旧仓。
- 石子、绳尺、泥板作为可见工具放在火堆旁，不放在菜单里。
- 居民、散粮、倒仓、被水冲坏的田形成三处视觉目标。
- 远景目标：倒仓、断田、远处市场轮廓；中景目标：散粮、混杂材料、居民动作；近景工具：石子、绳尺、碗、泥板。

交互：

- 孩子可拖动物品、点击居民、拖动石子到计数板。
- 不出现“第 1 课：计数”。
- 居民只说世界需求，例如：“我们不知道粮食够不够今晚。”
- 触摸居民会看到“饿/困惑/有力气”的状态变化。
- 触摸远处倒仓会得到世界反馈：“没有粮仓，明天粮会坏。”

数学生成：

```text
不知道够不够
-> 需要一一对应
-> 需要计数
-> 需要留下记录
```

验收：

- 不解释情况下，4/6 儿童能指出“东西乱了，要整理/数清楚”。
- 4/6 儿童会主动触摸至少一个世界问题或实体工具。

### 8.2 清点：石子与刻痕

场景：

- 每个居民旁可放一个石子。
- 每份粮食也可放一个石子。
- 石子数量不一致时，系统不判错，而是让居民产生不同反应。

规则：

- 每个居民需要 1 份晚饭。
- 粮食数量少于居民数时，有人会饿。
- 多余粮食会进入仓储。

学习目标：

- 数物对应。
- 一一对应。
- 数量比较。
- 记录的必要性。

错误反馈：

- 如果少分，未分到粮的居民行动变慢。
- 如果重复分，粮食提前耗尽。
- 孩子可重新清点和分配。
- 反馈发生在居民和粮食上，不弹出“错误”结算。

### 8.3 分类：物资不是都能相加

场景：

- 木头、石头、谷物、种子混在一起。
- 营地有 4 个自然区域：能吃、能种、能建、能记录。

规则：

- 只有同类物资能合并计算。
- 1 个苹果不能和 1 块石头直接相加成“2 个可建材料”。
- 物资按用途进入不同系统。

学习目标：

- 分类标准。
- 单位意识。
- 同类项直觉。
- 数学对象必须先定义“是什么”。

错误反馈：

- 谷物放进建材区会腐坏。
- 石头放进食物区居民不能吃。
- 种子吃掉后第二天无法播种。
- 错误物资弹回原地，同时在对应区域留下短暂痕迹，让孩子知道“为什么不合适”。

### 8.4 分配：第一顿饭

场景：

- 3 个居民，若干份粮食。
- 孩子拖动粮食到每个居民碗里。

规则：

- 每人至少 1 份才算公平生存。
- 如果粮食剩余，剩余进入仓库。
- 如果粮食不够，必须选择采集或重新安排。

学习目标：

- 平均分。
- 余数。
- “总数、份数、每份数”的关系萌芽。

错误反馈：

- 分配不均时，被少分的人直接表现出不满或饥饿。
- 不是弹窗说“错误”，而是世界后果。
- 分对后，居民从坐下/虚弱状态变为站起/搬运状态，并自然走向下一个问题。

### 8.5 丈量：第一块田

场景：

- 洪水冲掉田地边界。
- 孩子获得一根绳尺和木桩。

规则：

- 用绳尺拉出边界。
- 田地必须由单位格组成。
- 田地太小，种子放不下；太大，水渠够不到。
- 6 格田允许 2x3 和 3x2 两种标准解。
- 1x6 作为低效解：面积够，但水渠照料距离长，产量打折；用于引出“同面积不同形状”的体验。

学习目标：

- 长度。
- 起点对齐。
- 单位格。
- 面积来自单位密铺。
- 乘法阵列的前置经验。

错误反馈：

- 边界不闭合，水流冲走种子。
- 格子不足，种子无法全部播种。
- 格子过多，当前人力无法照料。
- 标准解让水流稳定、种子发芽；低效解可完成但会显示“照料太远，明天少收一点”。

### 8.6 建造：第一座粮仓

场景：

- 旧仓倒塌。
- 孩子要用木头、石头和已丈量的地基建粮仓。

规则：

- 粮仓底面决定容量。
- 入口宽度必须能让居民搬粮进入。
- 柱子位置不合理会倒塌。

学习目标：

- 空间组织。
- 容量直觉。
- 长宽与面积关系。
- 对称和稳定的早期经验。

错误反馈：

- 容量不足，粮食露天腐坏。
- 结构不稳，第二天粮仓倾斜。
- 入口太窄，搬运效率下降。
- 正确地基会让粮仓从旧仓残骸旁立起，成为新的远景记忆点。

### 8.7 泥板：文明记忆

场景：

- 一天结束，孩子把关键状态刻在泥板上。

记录项：

- 人数。
- 粮食剩余。
- 种子数量。
- 田地格数。
- 粮仓容量。

规则：

- 记录不完整，第二天部分状态需要重新清点。
- 记录清楚，居民可以自动执行部分工作。

学习目标：

- 符号。
- 表示。
- 记录。
- 可复算、可传承的程序。

文明意义：

```text
个人经验
-> 符号记录
-> 群体协作
-> 文明延续
```

### 8.8 多解法与规则实验

首版必须支持有限但真实的多解法，不做唯一答案式关卡。

| 问题 | 成立解法 | 低效/错误解法 | 反馈 |
|---|---|---|---|
| 田地 6 格 | 2x3、3x2 | 1x6、断裂形状、少于 6 格 | 标准解发芽；1x6 产量打折；断裂漏水 |
| 分 3 份饭 | 1/1/1 | 2/1/0、3/0/0 | 公平则三人恢复；不公平则有人没力气 |
| 分类物资 | 按用途归位 | 谷物放建材、石头放食物、种子吃掉 | 正确槽发光；错误产生腐坏/无效 |
| 粮仓地基 | 2x2 整齐地基 | L 形、断裂、入口被堵 | 正确立仓；错误歪斜或搬运失败 |

多解法验收不看“是否通关”，而看孩子能否说出：

```text
为什么这个也行？
为什么那个虽然格数一样但不好？
为什么这个东西不能放那里？
```

### 8.9 数学反应系统

数学反应系统把知识点从“要讲的内容”改成“世界里发生的结果”。

```text
数学对象
-> 世界状态
-> 玩家操作
-> 数学反应
-> 世界反馈
-> 儿童解释
```

首版必须实现至少 5 个基础反应，以下先列 6 个候选反应：

| 反应名 | 输入 | 条件 | 世界结果 | 数学含义 | 儿童解释目标 |
|---|---|---|---|---|---|
| 同类合并 | 木头 + 木头 | 同用途、同单位 | 建材槽增加，火堆旁出现可用木料 | 分类、同类相加 | “一样的东西才能一起数。” |
| 异类弹回 | 木头 + 谷物 | 不同用途或单位 | 物品弹回，谷物出现短暂腐坏痕迹 | 单位/类别不一致不能直接运算 | “它们不是同一种东西。” |
| 公平饭桌 | 3 份饭 + 3 人 | 每人至少 1 份 | 三个居民恢复行动 | 一一对应、平均分 | “每个人都有一份才公平。” |
| 阵列发芽 | 6 颗种子 + 2x3/3x2 田 | 单位格闭合，格数匹配 | 种子稳定发芽 | 阵列、面积密铺 | “2 排，每排 3 个，一共 6 个。” |
| 长形低效 | 6 颗种子 + 1x6 田 | 面积够但形状过长 | 可以播种，但第二天产量打折 | 同面积不同形状效率不同 | “一样多，但照顾起来更远。” |
| 记忆延续 | 泥板记录 + 今日状态 | 记录完整 | 第二天自动恢复人口、粮食、田地状态 | 符号记录、可传承 | “写下来，明天就不会忘。” |

设计约束：

- 反应先发生，名称后出现。
- 每个反应必须绑定一个儿童解释问题。
- 同一反应必须在后续至少一个文明问题中复用。
- 反应失败时只给世界后果，不弹“答错了”。

### 8.10 远中近目标牵引

首版不使用任务列表作为主驱动。当前问题解决后，下一个问题通过场景变化出现：

| 当前完成 | 下一个目标如何出现 |
|---|---|
| 清点完成 | 食物区、建材区、种子区出现微光，提示物资要归位 |
| 分类完成 | 饿居民靠近碗，提示分饭 |
| 分饭完成 | 居民恢复行动，走向被冲坏的田 |
| 量田完成 | 种子发芽，旧仓残骸晃动，提示建仓 |
| 建仓完成 | 粮食进入仓，泥板亮起，提示记录 |
| 记录完成 | 第二天营地保留成果，远处露出市场/水渠的轮廓 |

## 9. 系统架构

### 9.1 玩法系统

```text
文明瓶颈系统
-> 环境引导系统
-> 数学反应系统
-> 资源系统
-> 实体工具系统
-> 核心设施系统
-> 居民反馈系统
-> 建造系统
-> 错误后果系统
-> 记录与传承系统
-> 学习观察系统
```

### 9.2 数学工具系统

| 工具 | 来自文明问题 | 数学概念 | 首次用途 | 后续复用 |
|---|---|---|---|---|
| 石子 | 不知道人数和粮食够不够 | 一一对应、计数 | 清点居民和粮食 | 清点材料、交易数量 |
| 分类区域 | 物资混乱 | 分类标准、单位 | 整理食物/建材/种子 | 合成、交易、仓储 |
| 碗 | 每个人要吃饭 | 平均分、余数 | 分第一顿饭 | 分工、分种子 |
| 绳尺 | 田界消失 | 长度、单位 | 丈量田地 | 修路、建桥、房屋尺寸 |
| 单位格 | 不知道地有多大 | 面积、密铺 | 播种田地 | 地板、仓库容量 |
| 泥板 | 明天会忘记 | 符号、记录 | 保存营地状态 | 账本、地图、历法 |

### 9.3 核心设施系统：文明火堆/营地工坊

文明火堆/营地工坊是首版长期设施，不是菜单入口。它让孩子知道“规则会沉淀在世界里”，每解决一个文明问题，火堆周围就出现一个可见变化。

| 阶段 | 火堆/工坊变化 | 解锁能力 | 数学规则 |
|---|---|---|---|
| 初始 | 火堆微弱，居民围坐 | 观察需求 | 数量不足、状态变化 |
| 清点后 | 火堆旁出现石子计数位 | 数清楚 | 一一对应、数量比较 |
| 分类后 | 火堆旁出现食物/种子/建材槽 | 分清楚 | 分类、单位 |
| 分饭后 | 出现饭碗分配位 | 分公平 | 平均分、余数 |
| 量田后 | 出现田地图案板 | 量准确 | 单位格、面积 |
| 建仓后 | 火堆旁出现仓储标记 | 建稳定 | 容量、结构 |
| 记录后 | 泥板立在火堆旁 | 记得住 | 符号、记录、传承 |

验收：

- 4/6 儿童完成试玩后能指出“以后回哪里继续帮小岛”。
- 3/6 儿童能说出火堆旁多了什么，以及它有什么用。

### 9.4 居民反馈系统

居民不是教师 NPC，而是规则的需求和后果载体。

| 居民 | 初始状态 | 数学规则触发 | 反馈 |
|---|---|---|---|
| 小禾 | 饿，盯着粮食 | 一一对应、分饭 | 吃饱后去田边，提示丈量田地 |
| 石叔 | 想修仓但材料混乱 | 分类、建材数量 | 材料正确后开始搬木头 |
| 泥婆 | 担心明天忘记 | 记录、符号 | 泥板完整后点亮火堆记录 |

约束：

- 居民台词只表达世界需求，不讲数学定义。
- 居民状态变化必须能让孩子反推操作是否有效。
- 首版居民不做养成、抽卡、好感度。

### 9.5 环境引导系统

| 引导对象 | 表现方式 | 目的 |
|---|---|---|
| 饿居民 | 坐下、动作慢、看向粮食 | 引导分饭和数量比较 |
| 散落物资 | 混在泥水边，无法直接使用 | 引导分类 |
| 冲坏田地 | 水流穿过断裂边界 | 引导丈量和闭合边界 |
| 倒塌粮仓 | 粮食暴露、旧柱倾斜 | 引导建仓和稳定结构 |
| 发光泥板 | 完成建仓后亮起 | 引导记录和传承 |

### 9.6 状态与后果

| 玩家行为 | 即时反馈 | 延迟反馈 |
|---|---|---|
| 清点正确 | 居民安心，粮食数量显示清楚 | 第二天可自动分配基础口粮 |
| 清点混乱 | 居民疑惑，粮食数不稳定 | 第二天重新清点，拖慢发展 |
| 分类正确 | 物资进入对应用途 | 可合成粮仓/田地/工具 |
| 分类错误 | 物资出现“不适用”表现 | 腐坏、浪费或无法建造 |
| 分配公平 | 居民恢复行动 | 劳动力可用于建造 |
| 分配不公平 | 居民不满或饥饿 | 劳动力下降 |
| 丈量正确 | 田地可播种 | 第二天产生食物 |
| 丈量低效 | 田地可播种但照料距离过长 | 第二天产量打折 |
| 丈量错误 | 田边漏水或格子不足 | 种子损失或产量下降 |
| 记录完整 | 泥板发光，居民记住规则 | 第二天部分操作自动化 |
| 记录缺失 | 泥板空白处提示不明 | 状态丢失，需要重做 |

## 10. 学习目标映射

### 10.1 MVP 对应小学数学底层能力

| 游戏动作 | 数学能力 | 教材关联 |
|---|---|---|
| 给每个居民放一个石子 | 一一对应 | 一年级上：数物对应 |
| 比较居民和粮食数量 | 比多少 | 一年级上：一一对应后看剩余 |
| 整理食物/种子/建材 | 分类标准 | 一年级下：分类与整理 |
| 合并两堆同类木头 | 加法合并 | 一年级上/下：加法意义 |
| 消耗木头建仓 | 减法去掉 | 一年级上/下：减法意义 |
| 给居民分饭 | 平均分 | 二年级：除法前置 |
| 用绳尺量田边 | 长度测量 | 二年级/三年级：长度单位 |
| 用单位格铺田 | 面积密铺 | 三年级：面积 |
| 记录状态到泥板 | 符号表示 | 从生活经验到数学符号 |

## 12. 发布与验证计划

### 12.1 阶段计划

| 阶段 | 目标 | 产物 | 时间 |
|---|---|---|---|
| P0 纸面原型 | 验证世界目标和数学动作是否成立 | 纸面流程、观察表 | 1-2 天 |
| P1 低保真网页/小程序原型 | 验证可操作闭环 | 可玩切片 | 3-5 天 |
| P2 6 名儿童测试 | 验证理解、修正、复玩 | 6 份记录表 | 2-3 天 |
| P3 PRD 决策复盘 | 判断继续、修改或暂停 | Go/No-Go 报告 | 1 天 |

### 12.2 测试脚本

不解释玩法，只说：

> 洪水刚退，小岛上的居民不知道今晚怎么活下来。你可以摸摸看，看看能帮他们做什么。

观察者只记录，不教学。

结束后问 8 个问题：

1. 你刚才最先想帮他们解决什么？
2. 为什么要数清楚粮食？
3. 为什么这些东西不能都放在一起？
4. 为什么要用绳子量田？
5. 如果明天你不在，居民怎么知道今天还剩多少东西？
6. 2x3 和 3x2 为什么都可以？1x6 为什么看起来也有 6 格但不太好？
7. 火堆旁多了什么？下次你会回哪里继续帮小岛？
8. 你看到哪两个东西放在一起会发生变化？为什么？

### 12.3 Go/No-Go

| 决策 | 条件 |
|---|---|
| GO | H1-H5 至少 4 项达标，且没有明显“像作业”的反馈 |
| ITERATE | H1/H2 达标但 H3/H4 不达标，说明交互需要改 |
| PIVOT | H3 达标但 H2/规则解释率不达标，说明只是任务游戏 |
| STOP | H1 不达标，孩子无法理解世界目标 |

### 12.4 交互体验验证动作

| 动作 | 做法 | 成功标准 | 失败含义 |
|---|---|---|---|
| A1 首屏环境测试 | 不给口头说明，让孩子看 30 秒 | 4/6 能说出营地出了什么问题 | 环境即教程失败 |
| A2 工具实体测试 | 石子、绳尺、泥板放在世界中 | 4/6 会主动使用至少一种工具 | 工具没有形成能力心智 |
| A3 错误实验测试 | 允许错放、错量、错建 | 3/6 能根据世界后果修正 | 错误反馈不可读 |
| A4 多解法测试 | 田地支持 2x3、3x2、1x6、断裂形状 | 3/6 能解释至少两种形状的差异 | 多解法只变成试错 |
| A5 远中近目标测试 | 同屏放倒仓、散粮、石子等三层目标 | 4/6 不看任务列表也能连续完成两步 | 动线仍依赖 UI |
| A6 数学反应测试 | 做至少 5 个反应，优先同类合并、异类弹回、公平饭桌、阵列发芽、长形低效；泥板记忆可作为第 6 个反应 | 3/6 能解释至少 2 个反应 | 反应只变成试错，不形成理解 |
| A7 火堆设施心智测试 | 工具和成果围绕文明火堆逐步解锁 | 4/6 能说出“回火堆继续做/看记录/修营地” | 核心设施心智没形成 |
| A8 居民反馈测试 | 居民只通过状态变化反馈，不讲知识 | 3/6 能根据居民变化修正分配/分类 | 反馈不可读 |
| A9 家长价值测试 | 给家长看“数学反应报告”：孩子触发了哪些反应、如何解释 | 4/6 家长能说出孩子学到的数学规则 | 家长仍觉得只是游戏 |

## 13. Roadmap

### 13.1 后续文明章节

| 版本 | 文明瓶颈 | 生成数学 | 工具/居民/建筑 | 区域产品包 |
|---|---|---|---|---|
| v0.2 市场开张 | 交换不公平 | 单位、重量、价格、比例前置 | 秤、砝码、交易摊、商人居民 | 市场区：公平交换反应 |
| v0.3 水渠与桥 | 水到不了田、路断了 | 长度、路径、周长、估算 | 绳尺升级、水渠板、桥梁材料、修渠居民 | 水渠谷：路径和度量反应 |
| v0.4 星星和农时 | 不知道什么时候播种 | 周期、日历、时间 | 观星台、农历牌、记录居民 | 观星台：周期和预测反应 |
| v0.5 图案工坊 | 建筑不好看也不稳定 | 对称、平移、旋转、镶嵌 | 地砖、窗花、纹样台、工匠居民 | 图案区：对称和结构反应 |
| v0.6 岛外贸易 | 别的部落记数方式不同 | 数字系统、位值制、零 | 港口、异族数字、算盘、账本 | 港口区：记数和换算反应 |
| v0.7 自动营地 | 重复工作太多 | 算法、流程、条件 | 机关板、条件牌、流程泥板 | 机关区：流程和自动化反应 |

版本约束：

- 每个版本必须是一个完整区域产品包，不是一个独立知识点。
- 每个区域至少包含 1 个文明瓶颈、1 个核心数学反应、1 个世界设施、1 个居民反馈角色、1 个可见长期变化。
- 不做高频日常任务，不用打卡压力维持活跃。

数清楚

-> 分公平
-> 量准确
-> 建稳定

-> 换得公

## 14. 风险与反方观点

### 14.1 最强反方

> 原神的交互成立，依赖高品质 3D 世界、美术、音乐、角色、战斗和长期内容产能。《小小文明岛》是低成本 2D 教育原型，过度参考原神可能导致范围膨胀、成本失控和目标偏移。

这个反方成立。因此本 PRD 的融合原则不是“更像原神”，而是只吸收四个结构：

1. 世界目标牵引。
2. 规则反应系统。
3. 长期核心设施。
4. 区域产品包。

### 14.2 风险清单

| 风险 | 为什么严重 | 应对 |
|---|---|---|
| 变成原神低配模仿 | 小学生和家长都会觉得粗糙，且无法和成熟商业游戏竞争 | 不学画风、战斗、抽卡和大世界，只学目标牵引和规则反馈结构 |
| 数学反应变成炫技反馈 | 孩子可能只记得动画，不理解数学关系 | 每个反应必须绑定儿童解释问题和复用场景 |
| 火堆/工坊变成菜单 | 一旦变成按钮入口，就失去世界内设施心智 | 火堆周围必须有永久实体变化，不允许只打开面板 |
| 成人觉得很有方法论，孩子觉得不好玩 | 文明史框架可能变成成人自嗨 | 首版只用儿童行为指标判断，不用成人主观判断 |
| 变成历史包装题目 | 会踩中“历史卡+数学题”的失败模式 | 禁止首版知识卡、名人讲解、公式弹窗 |
| 孩子会玩但没学到数学 | 建造玩法可能掩盖学习目标 | 必须做规则解释率和迁移测试 |
| 多解法导致教学失控 | 孩子可能通过乱试通关，但不能解释规则 | 多解法必须绑定复述测试 |
| 环境引导不够清楚 | 低年级儿童可能在场景里乱点，不知道目标 | 远景目标、居民状态和工具高亮必须分层设计 |
| 物理实验成本失控 | 若追求复杂物理和自由建造，会超过 MVP 能力 | 首版只做有限规则实验，不做自由物理沙盒 |
| 范围膨胀 | 文明史可扩展内容太多 | MVP 只做洪水第一天 |
| 家长看不懂价值 | 如果没有可观察证据，商业价值弱 | 输出试玩录像观察点和儿童原话 |
| 历史事实误用 | 不能把复杂文明史简化成伪历史 | 使用复合虚构岛屿，强调历史精神，不声称还原具体历史 |

## 15. 开放问题

| 问题 | 决策方式 |
|---|---|
| 产品最终名称是否沿用《小小文明岛》 | 先用工作名测试儿童理解和家长接受度 |
