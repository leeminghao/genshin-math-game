## 1. 产品一句话

**《折折数学塔》是一款小学生空间解谜数学游戏：孩子通过移动、旋转、折叠、密铺、测量、分组、配比、建模和数据判断来改变建筑世界，让角色走进下一扇门；每一条路能否成立，都由小学数学规则决定。**

产品概念：

> For 小学 1-6 年级孩子，优先 2-4 年级作为首批可用性验证用户，  
> in 放学后 10-15 分钟轻量探索、家长希望孩子真正理解数学而不是刷题的场景，  
> who has 抽象数学概念难以形成直觉、做题会但说不清规则的问题，  
> the product provides 一个由小学数学规则驱动的等距空间解谜塔，  
> so that 孩子通过操作建筑、观察失败、修正策略，形成数量、运算、单位、空间、分数、比例、代数、数据和概率直觉，  
> with advantage over 答题换皮类学习 App because 数学不是题目答案，而是世界运行规则。

## 2. 产品设计总纲

### 2.1 数学不是题目，而是世界规则

禁止做法：

- 门上写算式，答对门开。
- 把教材内容改成选择题、填空题、奖励按钮。
- 孩子通过背答案过关，而不是通过观察结构过关。

目标做法：

- “一一对应”表现为每个桥洞必须有一块石板。
- “位值制”表现为十个一块自动捆成一个十块。
- “面积”表现为单位方格铺满平台才可通行。
- “分数”表现为半块必须回到自己的整体。
- “比例”表现为建筑同步缩放后路径仍保持形状。
- “概率”表现为孩子先观察事件结果，再判断可能性。

### 2.2 全内容覆盖不等于首版全开发

本 PRD 必须覆盖小学数学全部内容，但产品开发分三层：

| 层级 | 目标 | 范围 |
|---|---|---|
| 知识蓝图 | 确保所有教材内容有产品位置 | 覆盖 1-6 年级上下册全部模块 |
| 机制库 | 把知识变成可复用游戏规则 | 配对、分组、位值、旋转、密铺、折叠、测量、坐标、比例、变量、数据、概率 |
| MVP | 验证核心玩法是否成立 | 先做 6-12 关，验证孩子是否能无讲解理解规则 |

### 2.3 基础数学系统的产品分层

依据 `skills/basic-math-system-methodology`，产品知识结构按以下顺序组织：

```text
数的分类与数量感
-> 数的表示与位值
-> 加减乘除与逆运算
-> 精度、估计、单位和测量
-> 比较、百分数、比例和比率
-> 代数、方程、公式、算法
-> 平面几何、立体几何、图形运动
-> 数据整理、统计描述、可能性判断
```

这个顺序约束关卡解锁：后续机制必须依赖前面已经玩懂的规则，不能把知识点打散成课程卡片。

## 3. 用户、场景与核心问题

### 3.1 核心用户

| 用户 | 定义 | 核心需求 |
|---|---|---|
| 主用户 | 小学 2-4 年级孩子 | 不读长说明也能玩；通过操作理解规则 |
| 低龄扩展 | 小学 1 年级孩子 | 从生活物体、配对、位置、图形、钟表进入数学 |
| 高龄扩展 | 小学 5-6 年级孩子 | 需要分数、比例、体积、百分数、变量关系的直觉化体验 |
| 家长 | 购买与陪伴者 | 看见孩子不是乱玩，而是在形成可复述的数学概念 |
| 教师/教培 | 使用与传播者 | 可投屏讨论“为什么这条路通了/不通” |

### 3.2 核心问题

小学数学学习的关键问题不是“不会点答案”，而是：

1. 知识点被割裂，孩子不知道它们如何递进。
2. 抽象概念缺少可操作经验，例如单位、面积、分数、比例、变量。
3. 做题反馈只告诉对错，不能让孩子看见错误结构。
4. 普通数学游戏容易把数学包成奖励系统，孩子玩奖励，不玩数学。

### 3.3 产品目标

产品目标：

- 让孩子主动探索数学机关。
- 让 1-6 年级核心数学内容都有可操作世界规则。
- 让孩子在玩后能说出“我发现了什么规则”。
- 让家长端能看到完整知识图谱，而不是只看到分数。

非目标：

- 首版不做全年级全部可玩关卡。
- 不做题库、不做考试排名、不做每日打卡惩罚。
- 不复制任何已有游戏的 IP、美术资产、人物或关卡。

| 分数混合运算 | 运算律推广、线段图 | 分数机关链 | 整数运算律也可迁移到分数 | 能分步/综合列式 |
| 百分数 | 分母 100、互化、百分率 | 百分塔 | 百分数是统一比较标准 | 能在分数小数百分数间转换 |

### 6.2 每座塔的关卡配方

每个教材模块至少需要 2 类关卡：

1. **建立直觉关**：只玩规则，不出现正式术语。
2. **迁移应用关**：换场景，验证孩子是否能迁移。

每个关卡必须包含：

- 一个可见数学对象。
- 一个可操作机关。
- 一个错误后能看见的结构问题。
- 一个角色路径验证。
- 一个家长端概念标签。

## 7. 核心玩法

### 7.1 最小核心循环

1. 观察：孩子看到角色、门、断开的建筑规则。
2. 假设：孩子判断哪里能拖、转、折、配、铺、量、分组。
3. 操作：改变建筑状态。
4. 验证：点门，角色尝试通行。
5. 反馈：路通则角色进门；路不通则停在结构错误处。
6. 沉淀：家长端记录概念，儿童端只保留极短规则动画。

### 7.2 交互原则

| 原则 | 要求 |
|---|---|
| 少 UI | 关卡主画面占 85% 以上，不放任务列表 |
| 机关即知识 | 可交互物必须承载数学规则 |
| 门即验证 | 点门不是提交答案，而是角色尝试走路 |
| 失败可看见 | 错误必须表现为缺口、错位、剩余、悬空、单位不一致 |
| 文字后置 | 儿童端先操作后文字，家长端再显示术语 |
| 不照搬 IP | 只使用空间解谜原则，视觉、角色、叙事、关卡全部原创 |

## 8. MVP 范围

### 8.1 MVP 核心假设

如果把小学数学规则变成空间建筑机关，而不是题目卡，孩子能在无成人讲解的情况下完成首批关卡，并能复述至少一个规则。

### 8.2 MVP 用户

- 首测用户：小学 2-4 年级。
- 低龄旁测：小学 1 年级，验证配对/位置/图形。
- 高龄旁测：小学 5 年级，验证分数整体/面积割补。

### 8.3 MVP 必须做

| 模块 | 内容 | 验收标准 |
|---|---|---|
| 塔地图 | 6-12 个可点关卡入口 | 孩子 5 秒内知道点哪里开始 |
| 角色门验证 | 点门后自动寻路 | 路通进门，路不通停在错误处 |
| 机关系统 | 配对、旋转、阵列、密铺、分数整体、坐标 | 每类至少 1 个可玩关 |
| 数学反馈 | 缺口、剩余、错位、单位不同、方向不对 | 错误后 3 秒内能看见问题 |
| 三段提示 | 弱提示、结构提示、关键机关高亮 | 不直接给答案 |
| 家长概念报告 | 概念标签、尝试次数、提示使用、复述记录 | 不排名、不打分羞辱 |

### 8.4 MVP 明确不做

| 不做 | 原因 |
|---|---|
| 首版开发 80+ 模块全部关卡 | 会导致每个概念浅且产能失控 |
| 选择题/填空题 | 违背“数学是世界规则” |
| 排行榜/金币/抽卡 | 让动机偏离探索 |
| 长剧情讲解数学史 | 首版验证交互，不验证叙事 |
| 自由编辑器 | 等机制库稳定后再做 |

## 10. 关键关卡交互脚本

### 10.1 一步一石桥

- 学习目标：一一对应。
- 初始画面：三段断桥、三块石板、角色在左侧、门在右侧。
- 操作：孩子拖/点石板填桥洞。
- 错误：多出的石板无法放入，停在旁边。
- 成功：每个缺口都有石板，门发光，角色走入门。
- 家长端标签：一一对应、比较、剩余。

### 10.2 十个一成一个十

- 学习目标：位值制。
- 初始画面：十个小方块散落，十位门需要一个十块。
- 操作：把 10 个一块推入捆扎机。
- 错误：9 个无法捆，11 个会剩 1 个。
- 成功：10 个一自动变成 1 个十块。
- 家长端标签：十进制、位值、数的组成。

### 10.3 转 90 度

- 学习目标：旋转点、方向、角度。
- 初始画面：平台端点断开，蓝色圆环可转动。
- 操作：旋转楼梯到 90 度。
- 错误：0/180/270 度端点悬空。
- 成功：端点吸附，门发光。
- 家长端标签：旋转、直角、图形运动。

### 10.4 铺满广场

- 学习目标：面积是单位格密铺。
- 初始画面：3×4 空网格，旁边有单位方块。
- 操作：把单位方块吸附到网格。
- 错误：重叠弹回，留洞时角色停下。
- 成功：12 个单位格铺满。
- 家长端标签：面积、单位密铺、乘法阵列。

### 10.5 半月折廊

- 学习目标：分数依赖整体。
- 初始画面：小月门、大月门，各缺一半；地上有两块 1/2。
- 操作：把半块放回对应整体。
- 错误：小整体的 1/2 放到大整体时边缘错位。
- 成功：两个半块分别归位。
- 家长端标签：分数单位、部分-整体、整体可变。

### 10.6 割补桥

- 学习目标：未知图形可通过割补变成熟悉图形。
- 初始画面：斜四边形平台不能直接通行。
- 操作：切下一块，平移到另一侧，拼成长方形桥。
- 错误：切错位置会留下缺口。
- 成功：拼成规则图形，角色通行。
- 家长端标签：割补转化、面积公式推导。

## 13. 数据与验证指标

| 指标 | 目标 | 失败含义 |
|---|---|---|
| 首关完成率 | >= 90% | 可操作目标不清 |
| 前 6 关完成率 | >= 70% | 难度或提示失控 |
| 单关平均时长 | 1-3 分钟 | 太短无思考，太长易挫败 |
| 提示使用率 | 20%-50% | 过低太简单，过高机制不清 |
| 规则复述率 | >= 60% | 只是乱点过关 |
| 家长学习价值认可 | >= 70% | 无题目导致学习价值不可见 |
| 概念迁移成功率 | >= 50% | 关卡之间没有形成方法论递进 |

试玩记录必须包含：

- 孩子是否主动观察机关。
- 是否在失败后调整策略。
- 是否能说出“为什么路通/不通”。
- 是否能把上一关规则迁移到下一关。
- 家长是否能从报告理解教材对应关系。

### 14.4 长期版本

- 目标：从固定关卡走向创造性数学建筑。
- 范围：孩子可用规则块搭建自己的数学谜题。
- 前提：核心机制库稳定，且孩子能正确使用规则块。

## 15. 风险与反方观点

| 风险 | 反方观点 | 应对 |
|---|---|---|
| 内容全覆盖导致产品臃肿 | 把 80 个模块全做进游戏，可能变成课程软件 | PRD 覆盖全部，MVP 只验证核心机制 |
| 孩子只玩机关不学数学 | 空间谜题不会自动产生概念 | 每关必须有可视错误和复述测试 |
| 部分知识不适合空间化 | 统计、概率、时间、货币可能不像几何那样自然 | 允许用数据花园、市集、概率盒等非几何场景，但仍保持世界规则 |
| 家长看不见学习价值 | 没有题目和分数，家长可能误判为纯游戏 | 家长端显示教材模块、方法论、复述证据 |
| 关卡产能不足 | 手工空间谜题制作慢 | 建机制模板和编辑器，优先复用机关 |
| 低龄难度过高 | 空间谜题可能超出一年级理解 | 一年级只做生活物体、配对、分类、位置、钟表 |
| 抄袭风险 | 过度模仿已有空间解谜游戏 | 只借低 UI、建筑机关、角色门验证等原则；美术、角色、关卡原创 |

## 16. 立项建议

建议：**继续做低保真可玩验证，但 PRD 和内容架构按全小学数学体系设计。**

理由：

1. `books/小学数学/核心方法论骨架.md` 已经给出完整 12 册数学递进，本产品必须以全链路为目标，否则会变成几个孤立机关。
2. `basic-math-system-methodology` 明确要求数学是从数、表示、运算、单位、关系、空间、数据、不确定性逐层搭建的体系，关卡解锁必须体现递进。
3. `prd` 方法要求 MVP 不是全量功能，而是验证核心假设的最小产品包。因此本 PRD 覆盖全内容，开发必须分阶段。

Go 条件：

- 10 名 2-4 年级孩子试玩，首关完成率 >= 90%。
- 前 6 关完成率 >= 70%。
- >= 60% 孩子能复述至少一条数学规则。
- >= 70% 家长认可“这不是刷题换皮”。
- 至少 2 个关卡能证明孩子会从上一关迁移规则。

No-go 或转向条件：

- 孩子需要成人解释才能找到机关。
- 过关后说不出任何数学发现。
- 家长无法理解学习价值。
- 关卡制作成本高到无法覆盖完整知识图谱。
