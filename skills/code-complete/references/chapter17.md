# Chapter 17 - 常见的控制问题

## 核心观点

- 控制复杂度来自布尔表达式、嵌套、空语句、块结构和非结构化流程。
- 结构化编程的价值在于让程序路径更可理解和可验证。
- 复杂度一旦超过读者承受范围，缺陷会急剧增加。

## 操作步骤

1. 简化布尔表达式，使用中间变量表达含义。
2. 明确复合语句块边界。
3. 避免空语句和容易误读的语法陷阱。
4. 降低嵌套层级，提取子程序或使用 guard clause。
5. 检查控制结构是否可按顺序阅读。
6. 评估复杂度，并对高复杂度代码拆分。

## 典型工具

- 布尔表达式简化。
- 嵌套深度检查。
- 圈复杂度。
- 结构化编程检查表。
- 控制流图。

## 案例要点

- 本章强调布尔表达式和深层嵌套是常见可读性风险。
- 结构化编程不是形式主义，而是帮助人理解和验证控制路径。
