# Chapter 19 - 文档

## 核心观点

- 最好的文档首先是清晰代码，注释不能弥补糟糕结构。
- 注释应解释意图、原因、约束和非显然决策，而不是复述代码。
- 编程风格本身就是文档的一部分。

## 操作步骤

1. 先通过命名和结构提升自说明性。
2. 删除重复代码含义的低价值注释。
3. 为算法选择、边界条件、外部约束和异常情况写注释。
4. 用模块/接口文档说明契约和使用方式。
5. 保持外部文档和代码一致。
6. 在评审中检查注释是否仍然准确。

## 典型工具

- 注释质量检查表。
- 接口文档模板。
- 设计决策记录。
- 文档生成工具。
- 代码即文档审查。

## 案例要点

- 本章讨论“注释还是不注释”，重点是注释的有效性。
- 好注释说明为什么这样写，坏注释只是把代码翻译成人话。
