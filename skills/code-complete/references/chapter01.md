# Chapter 01 - 欢迎进入软件创建世界

## 核心观点

- 软件创建不是单纯编码，而是详细设计、编码、调试、单元测试和部分集成活动的组合。
- 创建活动在项目工作量和缺陷来源中占比很高，不能被当作低级机械劳动。
- 源代码常常是系统唯一准确、最新的描述，因此代码质量直接决定长期维护能力。

## 操作步骤

1. 明确当前任务属于创建活动中的哪一类：详细设计、编码、调试、单元测试或集成。
2. 在编码前确认相关需求、设计和接口是否足够支撑实现。
3. 把代码质量视为项目质量的核心资产，而不是交付后的清理项。
4. 对创建活动进行计划、检查和复盘。

## 典型工具

- 软件创建范围清单。
- 创建活动任务分解表。
- 源代码质量检查表。
- 缺陷来源统计表。

## 案例要点

- 书中强调创建活动在不同规模项目中可占 30% 到 80% 工作量，且大量错误来自创建阶段。
- 创建处于需求/设计与测试之间的枢纽位置；前期不清、后期测试不足，都会在代码中放大。
