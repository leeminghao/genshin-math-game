# Chapter 27 - 系统集成

## 核心观点

- 集成方式直接影响项目风险。
- 增量集成优于一次性大爆炸集成，因为它更早暴露接口和行为问题。
- 集成不是最后一步，而应贯穿开发过程。

## 操作步骤

1. 定义集成顺序和依赖关系。
2. 优先集成高风险接口和核心路径。
3. 每次集成保持小步、可验证。
4. 为未完成模块使用桩或驱动。
5. 每次集成后运行自动测试。
6. 记录集成问题并回溯接口契约。

## 典型工具

- 增量集成计划。
- 集成依赖图。
- 桩和驱动。
- 持续集成。
- 集成测试。
- 发布检查清单。

## 案例要点

- 本章强调分段与递增集成的重要性。
- 一次性集成会把大量问题叠在一起，导致定位困难和计划失控。
