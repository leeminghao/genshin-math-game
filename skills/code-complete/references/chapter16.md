# Chapter 16 - 少见的控制结构

## 核心观点

- goto、return、递归等控制结构不是绝对禁止，但必须服务清晰性。
- 少见控制结构容易打断阅读路径，应谨慎使用并限制范围。
- 递归适合天然递归问题，但要控制终止条件、栈深和性能风险。

## 操作步骤

1. 判断特殊控制结构是否真的比普通结构更清楚。
2. 对 early return 保证资源清理和状态一致。
3. 对 goto-like 结构限制在错误清理等清晰场景。
4. 对递归明确基准条件和递归推进。
5. 检查递归深度、性能和可替代迭代实现。
6. 为特殊控制结构增加测试和必要说明。

## 典型工具

- 特殊控制结构审查表。
- 资源清理检查。
- 递归终止条件检查。
- 栈深风险评估。
- 等价迭代方案比较。

## 案例要点

- 本章讨论 goto、return 和递归，态度不是教条禁止，而是看是否提升整体清晰性。
- 在某些语言中，集中清理错误路径可能比重复清理更安全。
