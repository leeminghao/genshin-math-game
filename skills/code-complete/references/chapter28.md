# Chapter 28 - 代码调整策略

## 核心观点

- 性能调整必须在正确性和清晰性之后进行。
- 没有测量的优化是猜测，可能浪费时间并损害可维护性。
- 大多数性能问题集中在少数热点路径，应先定位瓶颈。

## 操作步骤

1. 先确认程序正确并有基本测试保护。
2. 明确性能目标和用户可感知指标。
3. 使用 profiling 或度量定位瓶颈。
4. 判断瓶颈来自算法、I/O、数据结构、重复工作还是低层代码。
5. 只调整关键路径。
6. 调整后重新测量，并评估可读性损失。

## 典型工具

- Profiling。
- 性能基准。
- 热点路径分析。
- 性能目标表。
- 调整前后对比。

## 案例要点

- 本章强调代码调整前要有策略和证据。
- 低效率情况应通过测量识别，而不是凭经验猜测。
