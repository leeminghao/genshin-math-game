# Chapter 26 - 调试

## 核心观点

- 调试应是有假设、有证据的系统过程，而不是随机试错。
- 找错和改错是两个阶段；未理解根因前的修改容易制造新问题。
- 调试心理很重要，程序员必须承认自己的假设可能错误。

## 操作步骤

1. 稳定复现问题。
2. 收集最小必要信息。
3. 形成明确假设。
4. 缩小范围并验证假设。
5. 找到根因后再修改。
6. 验证修复并检查相邻路径。
7. 添加回归测试或诊断日志。

## 典型工具

- 调试器。
- 日志和追踪。
- 二分定位。
- 最小复现。
- 断言。
- 回归测试。
- 根因分析表。

## 案例要点

- 本章区分找错、修改错误、调试心理因素和调试工具。
- 调试失败常来自过早下结论和只修症状。
