# Chapter 23 - 软件质量概述

## 核心观点

- 软件质量不是测试阶段补出来的，而是在整个创建过程中构建出来的。
- 质量有多个维度：正确性、可靠性、效率、完整性、可用性、可维护性、灵活性、可测试性等。
- 不同质量目标之间存在取舍，必须明确优先级。

## 操作步骤

1. 明确本项目最重要的质量属性。
2. 为质量属性定义可观察标准。
3. 在需求、设计、编码、评审、测试中分别布置质量活动。
4. 评估不同质量方法的成本和效果。
5. 尽早做质量保证，不等到末尾。
6. 用缺陷数据改进流程。

## 典型工具

- 软件质量属性表。
- 质量目标优先级。
- 缺陷预防计划。
- 质量保证活动矩阵。
- 缺陷统计。

## 案例要点

- 本章强调提高质量的方法有多种，效果不同。
- 质量保证越早介入，修复成本越低，效果越稳定。
