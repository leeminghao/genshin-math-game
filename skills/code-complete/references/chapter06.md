# Chapter 06 - 模块化设计

## 核心观点

- 模块化的核心是信息隐藏：把容易变化和复杂的实现细节封装在稳定接口之后。
- 好模块高内聚、低耦合，并能把系统复杂度分解成可理解单元。
- 模块边界设计不好，会导致全局知识扩散和维护成本上升。

## 操作步骤

1. 找出系统中最可能变化的设计决策。
2. 围绕变化点建立模块边界。
3. 为模块定义清晰接口、输入输出和错误契约。
4. 隐藏内部数据结构、算法、资源管理和第三方依赖。
5. 检查模块之间是否存在循环依赖或共享可变状态。
6. 用测试验证模块契约。

## 典型工具

- 信息隐藏清单。
- 模块职责表。
- 内聚/耦合矩阵。
- 接口契约说明。
- 依赖图。

## 案例要点

- 本章强调模块化不是简单分文件，而是隐藏设计决策。
- 在任何语言中都可以实现模块化；语言机制不同，但信息隐藏原则通用。
