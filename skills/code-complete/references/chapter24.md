# Chapter 24 - 评审

## 核心观点

- 评审是高效的软件质量保证方法，通常比单纯测试更早发现缺陷。
- 代码检查应有结构、有角色、有检查表，而不是随意浏览。
- 评审目标是发现问题和传播知识，不是羞辱作者。

## 操作步骤

1. 选择合适评审形式：走查、同伴评审、正式检查。
2. 准备被评审材料和上下文。
3. 使用检查表聚焦常见缺陷。
4. 控制评审范围和时间。
5. 记录缺陷，不在会上展开大规模重构争论。
6. 跟踪修复和复查。

## 典型工具

- 代码评审清单。
- 正式检查流程。
- 缺陷记录表。
- 评审角色分工。
- Pull Request 模板。

## 案例要点

- 本章说明评审在质量保证中占重要地位。
- 检查和其他评审方法能在代码运行前暴露设计、逻辑和可维护性问题。
