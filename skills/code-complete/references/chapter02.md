# Chapter 02 - 利用隐喻对编程进行更深刻的理解

## 核心观点

- 隐喻帮助程序员理解软件开发的本质，但错误隐喻会导致错误实践。
- 软件开发不是机械翻译，更像建筑、写作、探索和工具使用的组合。
- 不同项目和阶段需要不同隐喻：有时要严谨施工，有时要迭代探索。

## 操作步骤

1. 识别团队当前默认隐喻：写代码、造房子、修补、探索、制造等。
2. 判断隐喻是否匹配项目不确定性和规模。
3. 对稳定需求使用工程/建筑隐喻，强调计划、结构和检查。
4. 对探索任务使用迭代/实验隐喻，强调试验、反馈和调整。
5. 避免把编码理解成把设计机械翻译成语法。

## 典型工具

- 项目隐喻选择表。
- 不确定性/规模评估表。
- 工程式与探索式工作方式对照表。

## 案例要点

- 建筑隐喻适合强调先决条件、设计、施工质量和检查。
- 写作隐喻适合强调草稿、修改、重写和编辑。
- 工具箱隐喻提醒程序员不要迷信单一方法，要按问题选择技术。
