# Chapter 09 - 数据名称

## 核心观点

- 命名是代码可读性的核心，不是表面风格问题。
- 好名称应表达含义、角色、范围、单位和领域语义。
- 坏名称会把复杂度转移给读者，并制造误用风险。

## 操作步骤

1. 先明确变量代表的真实概念。
2. 使用领域语言命名，而不是实现细节或临时想法。
3. 对特定数据类型采用一致命名规则。
4. 避免过短、含糊、误导、相似和只靠类型区分的名称。
5. 在局部短作用域内才允许非常短的临时名称。
6. 遵守项目已有约定，除非约定本身明显损害理解。

## 典型工具

- 命名检查表。
- 领域词汇表。
- 禁用名称清单。
- 命名约定。
- 缩写审查表。

## 案例要点

- 本章讨论特定数据类型命名、正式/非正式命名约定、匈牙利命名和短名称风险。
- 重点不是某个命名体系，而是名称是否帮助读者理解意图。
