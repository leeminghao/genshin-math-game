# Chapter 30 - 软件优化

## 核心观点

- 软件优化不仅是代码微调，还包括需求、架构、算法、数据结构和资源使用的整体取舍。
- 优化应服务真实目标，而不是追求抽象的“更快”。
- 清晰代码和可测系统是有效优化的前提。

## 操作步骤

1. 明确优化类型：速度、内存、I/O、启动时间、吞吐、延迟、体积。
2. 确认优化是否真正必要。
3. 优先从需求和算法层面寻找大收益。
4. 对新程序先设计清晰结构，再建立性能基线。
5. 优化后检查正确性、可维护性和回归风险。
6. 记录优化决策。

## 典型工具

- 性能目标矩阵。
- 算法复杂度分析。
- 资源使用剖析。
- 性能回归测试。
- 优化决策记录。

## 案例要点

- 本章区分不同软件优化种类，提醒不要把所有问题都当成代码微调。
- 编写新程序时，应先建立可维护结构，再根据证据优化。
