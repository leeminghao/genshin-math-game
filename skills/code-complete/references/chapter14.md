# Chapter 14 - 条件语句

## 核心观点

- 条件语句应简单、完整、可读，并明确覆盖正常和异常路径。
- 复杂条件容易隐藏业务规则，应通过命名、拆分或表驱动降低复杂度。
- case/switch 适合互斥分支，但必须处理默认和遗漏情况。

## 操作步骤

1. 让常见路径和异常路径都清楚可见。
2. 将复杂布尔表达式提取为有意义名称。
3. 避免深层嵌套，必要时使用 guard clause。
4. 检查 if/else 分支是否完整互斥。
5. 使用 case/switch 时检查默认分支和枚举覆盖。
6. 对业务规则密集条件考虑表驱动或策略对象。

## 典型工具

- 条件分支检查表。
- 布尔表达式命名。
- guard clause。
- 分支覆盖表。
- 表驱动替代。

## 案例要点

- 本章分别讨论 if 和 case 语句，重点是清晰表达选择逻辑。
- 条件语句质量直接影响缺陷定位和测试覆盖设计。
