# Chapter 07 - 高级结构设计

## 核心观点

- 高级设计的目标是控制复杂度，并让系统在变化中保持可理解。
- 结构化设计、面向对象和往返设计等方法都只是工具，不能替代设计判断。
- 设计不是一次完成的，应在实现反馈中迭代调整。

## 操作步骤

1. 明确主要复杂度来源：业务规则、数据流、状态、并发、外部系统或性能。
2. 选择合适设计方法，而不是套用流行范式。
3. 划分层次、模块、对象或数据流。
4. 定义关键接口和变化点。
5. 通过原型、代码和评审往返验证设计。
6. 在设计过度和设计不足之间保持平衡。

## 典型工具

- 结构化设计图。
- 面向对象职责划分。
- 数据流图。
- 设计评审。
- 往返设计记录。
- 复杂度风险表。

## 案例要点

- 本章讨论结构化设计和面向对象，但重点不是技术标签，而是设计是否降低复杂度。
- 往返设计提醒团队：实现会暴露设计问题，设计要允许根据反馈修正。
