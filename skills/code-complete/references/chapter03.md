# Chapter 03 - 软件创建的先决条件

## 核心观点

- 编码前置条件不足，会把需求、架构和约定问题转化为代码混乱。
- 创建前必须确认问题定义、需求、架构、语言、工具和编程约定。
- 前期准备不是官僚流程，而是降低返工和缺陷的工程保险。

## 操作步骤

1. 检查问题定义是否清楚：要解决什么，不解决什么。
2. 检查需求是否可实现、可测试、无重大冲突。
3. 检查架构是否给出模块边界、关键接口和主要技术决策。
4. 检查语言和技术栈是否适合问题规模和团队能力。
5. 检查编码约定、错误处理、日志、测试和目录结构是否明确。
6. 如果前置条件不足，先补齐关键缺口，再进入实现。

## 典型工具

- 编码前置条件检查表。
- 需求就绪度检查表。
- 架构决策记录 ADR。
- 编码约定清单。
- Go/No-Go 创建评审表。

## 案例要点

- 书中强调问题定义、需求、结构设计和编程约定都是创建先决条件。
- 小项目可以轻量化准备，但不能完全跳过；项目越大，前置条件越重要。
