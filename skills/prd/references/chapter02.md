# 第02章 产品：关键词与分类

## 核心观点

- 产品是“解决某个问题的东西”。
- “某个”强调定位；“问题”包含用户、需求、场景；“东西”是解决方案。
- 定义产品时不能脱离用户关系、需求类型、用户类型和产品形态。
- 产品分类不是学术分类，而是帮助确定设计、运营、商业和增长打法。

## 操作步骤

1. 明确产品服务的“某个”对象，排除非目标用户。
2. 描述用户在什么场景下遇到什么问题。
3. 把问题转成解决方案，但不要过早绑定具体功能。
4. 按用户关系、需求类型、用户类型、产品形态分类。
5. 根据分类推导产品策略：冷启动、网络效应、运营方式、商业模式。

## 典型工具

- 用户-需求-场景-解决方案四格表。
- 产品分类矩阵：2C/2B、工具/内容/社区/交易、单边/双边/多边。
- 定位排除清单：服务谁、不服务谁。
- 场景卡片：时间、地点、触发、任务、痛点、替代方案。

## 案例要点

- 章节用“解决某个问题的东西”建立产品定义，避免产品讨论陷入功能堆砌。
- 对多边产品、工具产品、内容产品、平台产品等不同类型的区分，提示产品设计必须结合增长和运营逻辑。
- 对 PRD 的启示：需求描述必须同时包含用户、需求、场景和解决方案假设。
