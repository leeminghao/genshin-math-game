# 第07章 执行：立项组队与研发生产

## 核心观点

- 从“想清楚”到“做出来”的关键是立项、资源、团队和研发协作。
- 原型验证和 NPS 可帮助在投入研发前降低不确定性。
- 立项不是走流程，而是搞定人、钱、政策、优先级和组织承诺。
- 小团队需要高密度沟通，大公司需要更清晰的节点和协同机制。

## 操作步骤

1. 用原型、Demo、访谈或小流量测试验证核心假设。
2. 准备立项材料：目标、用户、需求、范围、资源、风险、里程碑、收益。
3. 组建最小跨职能团队。
4. 明确研发生产中的产品职责：需求澄清、优先级、验收、变更、风险协调。
5. 建立关键节点评审：立项、方案、开发、测试、上线、复盘。
6. 对外部第三方依赖明确接口、交付物和验收标准。

## 典型工具

- 原型验证清单。
- NPS 或用户满意度问题。
- 立项一页纸。
- RACI 分工表。
- 里程碑计划。
- 风险登记表。
- 需求变更记录。

## 案例要点

- 产品委员会与关键节点用于说明产品决策需要组织机制支撑。
- 初创团队案例强调快速知己知彼、小团队协作、借助第三方力量。
- “产品经理要不要懂技术”讨论的核心不是成为工程师，而是理解约束、成本和协作语言。
