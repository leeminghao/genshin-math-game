# 第00章 开始：写在正文之前

## 核心观点

- 产品经理方法论也要先做“产品定位”：明确目标用户、使用场景、需求边界和交付方式。
- 本书面向“-1 到 3 岁”的泛产品经理，不只服务专职产品经理，也服务创业者、技术、设计、运营和传统行业转型者。
- 产品思维不是岗位专属，而是一套发现问题、定义问题、组织资源、验证结果的工作方法。
- 方法论有边界：适合入门与搭建知识地图，不能替代真实项目中的判断、实践和复盘。

## 操作步骤

1. 先判断读者/用户是谁：专职产品经理、泛产品经理、创业者、跨职能协作者，还是传统行业转型者。
2. 明确当前问题处于哪个阶段：想清楚、做出来、推出去、持续成长。
3. 根据阶段选择章节方法，不要一上来追求完整流程。
4. 标记已知事实、假设和需要验证的问题。
5. 产出可用于行动的最小文档，而不是百科式说明。

## 典型工具

- 产品定位表：目标用户、场景、需求、解决方案、边界。
- 阅读/学习路径：按“想清楚、做出来、推出去”选择方法。
- 假设清单：事实、假设、待验证问题。
- 方法边界说明：适用、不适用、需要补充实践的部分。

## 案例要点

- 作者用写书本身类比做产品：一本书也需要目标用户、需求场景、定位、框架和使用方法。
- 书的定位从专业产品经理扩展到“泛产品经理”，强调各岗位都可能需要产品思维。
- 重要启示：任何产品文档或方法论输出，都应先说明它为谁服务、解决什么问题、如何使用。
