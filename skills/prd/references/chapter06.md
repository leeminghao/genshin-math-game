# 第06章 功能：细化与打包

## 核心观点

- 一个功能要判断价值、成本和性价比，不能只看“有没有用”。
- KANO 模型帮助识别基础型、期望型、兴奋型、无差异和反向需求。
- MVP 的本质是尽可能多地放弃，用最小产品包验证核心假设。
- 需求和功能要同时按空间维度和时间维度管理。

## 操作步骤

1. 为每个功能写清用户、场景、需求、价值和验收标准。
2. 评估实现成本、协作成本、运营成本和维护成本。
3. 用 KANO 或价值/成本矩阵进行优先级判断。
4. 打包 MVP：保留核心路径，删除非验证核心假设的功能。
5. 输出产品架构图或功能列表。
6. 建立需求流程：收集、分析、评审、排期、开发、验收、上线、复盘。

## 典型工具

- 功能 DNA 表：用户、场景、价值、成本、优先级、验收标准。
- KANO 分类表。
- MVP 范围表：必须有、明确不做、延后做。
- 产品架构图。
- 功能列表和需求看板。

## 案例要点

- QQ 的 MVP 案例说明第一版产品不必完整，但必须验证核心价值。
- 功能分分合合的讨论提示：功能组织方式本质上服务于用户理解、使用路径和团队执行。
- 对 PRD 的启示：MVP 章节要明确“为什么不做”，否则范围会持续膨胀。
