# 第08章 成长：规划与迭代

## 核心观点

- 好产品不是一次做成，而是在规划和迭代中步步为营。
- 规划要同时看最短和最长：短期能落地，长期有方向。
- 敏捷不是不要计划，而是在价值观、原则和实践下快速反馈。
- 速度是竞争力，低成本验证可避免大规模浪费。
- 产品要与用户一起成长。

## 操作步骤

1. 定义长期方向：产品最终要成为什么。
2. 定义近期最小目标：下一版本要验证什么。
3. 建立版本节奏和迭代原则。
4. 用低成本实验验证关键假设。
5. 根据用户反馈、数据和业务变化调整路线图。
6. 定期复盘：目标是否达成、假设是否成立、下一步是否继续。

## 典型工具

- Roadmap：近期、中期、长期。
- 版本计划表。
- 假设验证表。
- 敏捷看板。
- 复盘模板：目标、结果、原因、行动。
- 用户成长路径图。

## 案例要点

- “只看最短和最长”提醒产品规划不要陷入中期伪精确。
- 烧钱抢时间和低成本验证的讨论说明速度与成本要一起看。
- 对 PRD 的启示：PRD 不只写当前版本，还要说明下一步验证和迭代方向。
