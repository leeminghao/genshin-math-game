# 第04章 需求：采集与用户研究

## 核心观点

- 需求采集要区分直接/间接、定性/定量、真实/非真实场景、是否与产品交互。
- 用户说出的需求只是线索，产品经理要理解更深层的动机和问题。
- 需求有不同深度：表层表达、场景问题、底层动机。
- 产品原则和初心是需求取舍的稳定锚点。

## 操作步骤

1. 明确要验证的问题，不为调研而调研。
2. 选择采集方法：访谈、观察、问卷、数据分析、可用性测试、客服反馈、社群反馈。
3. 区分用户说什么、做什么、为什么做。
4. 把需求抽象成用户类型、场景、问题、证据。
5. 用产品原则判断哪些需求收、哪些需求拒绝。
6. 把需求进入后续分析流程，而不是直接变成功能。

## 典型工具

- 用户访谈提纲。
- 观察记录表：场景、行为、障碍、替代方案。
- 需求采集矩阵：直接/间接、定性/定量、真实场景/非真实场景。
- 需求证据表：来源、频率、强度、样本、可信度。
- 产品原则清单。

## 案例要点

- “小得”的产品原则案例说明产品原则可以帮助团队抵御零散需求干扰。
- 知乎、豆瓣案例体现“初心”对产品气质和社区规则的长期影响。
- 美国宪法作为跨界参考，强调原则不是口号，而是后续决策和冲突处理的依据。
